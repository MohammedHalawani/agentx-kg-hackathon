# GPT-OSS v1 controlled paired benchmark protocol

Recorded: 2026-10-08T13:25:51+03:00. Protocol/source fixed before cloud evaluation. Companion references: 2026-10-07_gpt-oss-v1-evidence-audit.json and 2026-10-07_gpt-oss-v1-quality-rubric.md.

The benchmark compares openai/gpt-oss:20b and openai/gpt-oss:120b on 30 identical case-language inputs, six supported base categories with five distinct shipments each. Each category has three Arabic and two English complaints, so each model receives 18 Arabic and 12 English inputs. This is not a translation-paired bilingual test of every shipment. At most one escalation history per base category is selected where uniquely available; ordinary histories supply the remaining four. Seed 42 and case order are fixed; the default runner alternates 20B/120B for each case. Temperature is zero, request timeout 90 seconds, provider retry count zero for both.

Prepare uses local synthetic shipments Neo4j READ queries and local bge-m3 embeddings. No model generation or database writes occur. Only seeded Resolution rows with an observed boolean synthetic Outcome and no agent source are eligible. The generator's labels/actions and random outcomes are synthetic records, not independently adjudicated human SPL ground truth.

Each complaint is a symptom-style template plus factual shipment ID/city. Own local context retains policy/address/courier and all recorded event chronology, removing own FailureReason/category/description/resolution/outcome and retrospective shipment status. Runtime inputs and gold are separate files. Historical precedent may contain its recorded cause/action/outcome, as required for GraphRAG. Every FailureReason attached to the held-out shipment, including siblings on escalation cases, is excluded from first retrieval, all second-pass banks and scoring history. Membership snapshots enforce complete sibling exclusion.

First vector plus structural retrieval is frozen from factual ID/city with category_hint absent. Second retrieval has six frozen category-conditioned banks constructed with fixed category queries and the same first context; lookup uses the model's predicted category, never the seeded gold or model rationale. Both models therefore see identical evidence for the same predicted branch. Selection uses expanded retrieval candidate budgets before exclusion and retains the production similarity floor; these frozen retrieval budgets are benchmark controls, not claims about unchanged live retrieval performance.

Real extraction, JSON normalization, classifier, recommender, reviewer, business rules and compiled LangGraph AFL/no-grounding/capped rejection paths execute. Extraction output is measured but cannot change frozen contextual retrieval. Case files and writeback are dry sinks; unexpected database retrieval/write paths fail closed. Production execute disposition in the trace is a dry accepted recommendation only, labelled accepted_recommendation outside the trace, with writeback_executed=false and observed_success=null. This controlled benchmark differs from the full live Batch 2 integration proof.

The safe provider wrapper retains syntax/declared-shape/enum/range diagnostics, type-only exceptions, numeric token usage and latency. It never stores raw provider blocks, hidden reasoning, request bodies or exception text. Only normalized structured application stage/final outputs are retained. Completed failures and malformed-output fallback cases are persisted and skipped on resume. Manifest hashes cover runtime/gold/corpus/membership, production sources, evaluator source and templates; a nonsecret endpoint/settings fingerprint also prevents cross-configuration reuse. Existing result model/case/language/version/hashes must match. Reports read only the expected 30 case paths per model and reject mismatched result identity.

All headline case rates use 30 planned cases per model, including errors and no grounding; partial-run missing cases remain visible. Supported-base cause agreement and failed-attempt family agreement are primary descriptive label proxies. Raw escalation-prefix agreement is explicitly separate because production output vocabulary contains only six base causes. Pipeline agreement includes application defaults; valid-model agreement excludes malformed/missing/invalid final classifier output. Report first/final agreement and AFL improvements/regressions separately.

Action exact agreement compares a seeded action string; history plausibility uses only sibling-excluded observed synthetic history and is a proxy, not independent action appropriateness. Reviewer acceptance, acceptance with seeded-label disagreement, AFL retries, escalation and retrieval cause matching are descriptive signals. False acceptance/rejection are unavailable without independent gold. Per-category denominators are five, confusion counts include missing predictions/unattempted rows, and Wilson intervals on completed synthetic agreement illustrate broad uncertainty rather than establish production significance.

Native prompts are written in English and do not explicitly require an explanation language; the known action vocabulary is Arabic. The metadata field native_prompt_prose_language describes prompt language, not a required response language. Report complaint language, actual native prose language and Arabic action presence separately. Arabic action text does not establish Arabic rationale quality; editorial rubric review is separate. A clear Arabic explanation is not a wrong-language failure, and English prose on an Arabic complaint is a product observation rather than violation of a nonexistent requirement. Aggregate/per-stage model and pipeline mean/p50/p95 latencies, call/case diagnostic rates and exposed numeric usage are collected.

The local projection does not provide measured barcode/weight/gate/contact outcomes; some causes are underidentified. Barcode and weight complaints deliberately share symptoms. Multiple failures on a shipment can admit more than one recorded base cause, so selected-label agreement and any-recorded-shipment-cause agreement are separate. Thirty synthetic cases support an initial controlled comparison only. Neither model is preferred until paired results and quality review support that conclusion.
