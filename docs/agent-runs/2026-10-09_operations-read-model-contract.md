# Operations V2 read contract

Recorded 2026-10-09, Asia/Riyadh. Source owner: explore_backend. API wiring and ledger writes are owned separately.

`operations.read_model.OperationsReader(driver, database, dataset_id, config, clock=store.clock, store=store)` uses explicit isolated `shipments-v2-demo` target, fixed Cypher and `session(default_access_mode='READ').execute_read`. No provider, environment, DB writes or DDL. Immutable `V2Entity` observations are separate from mutable `OpsCase`/`OpsAudit` projections.

All operational routes are development-only. No split request parameter or fallback to V1/history/held-out exists. Historical data is exposed only as bounded verified precedent evidence or explicitly labelled aggregate synthetic history metrics.

## Pagination

Methods `queue`, `audit`, `explore` accept `cursor=None`, `limit=25`. Allowed limits: 25, 50, 100. Responses: `items`, `filtered_total`, `next_cursor`, `previous_cursor:null`, `metadata:{as_of,split:'development',synthetic:true,limit,filters,filter_choices}`. Queue metadata additionally has `buckets` indexed by actual workflow state, scoped to the supplied filters. City choices come from visible development shipments.

Ascending `(opened_at,entity_id)` for queue, `(occurred_at,entity_id)` for audit, `(recorded_at,entity_id)` for Explore. Cursor binds route, dataset, normalized filters and limit; freezes logical upper timestamp. Changed filters/limit reject. Native Neo4j DateTime values normalize recursively into aware UTC ISO strings; timestamp query parameters bind native Python aware datetimes. Ledger comparisons tolerate ISO strings or actual temporals with `datetime(...)`.

Cursors are opaque encoded data, not authorization tokens. Operational access is enforced independently by fixed queries. Pagination is not a database MVCC snapshot: existing case workflow changes can affect filtered membership between pages. IDs and keyset ordering avoid offset drift; clients refresh to see newly eligible rows.

## Routes for root wiring

- `GET /cases/queue` -> `reader.queue`: `workflow_state`, `operational_status`, `priority`, `city`, `cause`, `from_at`, `to_at`, `search`. FastAPI may expose `from`/`to` aliases while passing internal `from_at`/`to_at`. Items: `case_id,shipment_id,source_case_id,issue_summary,city,category,cause_codes,priority,workflow_state,operational_status,opened_at,as_of,state_version,synthetic`.
- `GET /audit` -> `reader.audit`: `shipment_id,case_id,event_type,actor,model,workflow_state,from_at,to_at,search`. Items: `id,timestamp,shipment_id,case_id,event_type,actor,decision,result,from_state,to_state,model,synthetic`. No unrestricted raw audit payload or model reasoning. Filter choices derive visible ledger events.
- `GET /explore` -> `reader.explore`: `filter=needs_attention|all|critical|sla_risk|stalled|unreconciled|delivery_dispute|delivered`, `city,cause,service_type,shipment_class`. Service/class filters accept actual `ServiceLevel`/`ShipmentType` entity IDs or their catalog aliases case-insensitively. `metadata.filter_choices` supplies aliases; `metadata.catalog_choices` supplies `{id,label}` mappings. Current frozen catalog aliases are STANDARD/EXPRESS/APPOINTMENT and SMALL/BULKY. Items: `shipment_id,status,operational_status,city,origin_city,destination_city,flow_type,cause_codes,priority,case_id,workflow_state,as_of,synthetic,origin,destination`. Points are actual synthetic facility/effective address coordinates with `entity_id,source`; address also `accuracy_m`. Missing coordinates return null. Delivered means latest observed status at the visible snapshot; resolved means authoritative ledger closure.
- `GET /shipments/{shipment_id}` -> `reader.shipment_detail`: optional server-controlled snapshot. Returns `shipment_id,as_of,synthetic,evidence,reasoning,route_layers`.
- `GET /cases/{case_id}` -> `reader.case_detail`: adds authoritative ledger `workflow_state,state_version,priority,operational_status,recommendation,review,outcome,decisions,executions,run`. Fresh `reasoning.workflow_state` is a proposed triage route and never replaces the stored workflow or human decision. Requires injected store for complete action records.
- `GET /decisions` -> `reader.decisions`: `as_of,synthetic,development:{case_counts,verified_outcome_count,succeeded,failed,pending_outcome_count,verified_success_rate,denominator},history:{verified_outcome_count,succeeded,failed,verified_success_rate,denominator},limitations`. Null rates when no eligible observed denominator. Synthetic fixture history is not measured model performance.

Bad parameters -> ValueError (HTTP 400); absent/nonoperational identity -> LookupError (404); oversized detail -> ReadModelUnavailable (503). Up to 1000 own evidence nodes, 400 relevant shared catalog nodes, 2000 edges. Overbound fails closed, never silently reasons from a truncated context. Catalog retrieval follows explicit own references and outbound type/city ancestors; never walks from a shared vehicle type into another vehicle's journey.

Workflow vocabulary includes REJECTED as well as OPEN, INVESTIGATING, NEEDS_EVIDENCE, RECOMMENDATION_READY, AWAITING_APPROVAL, ACTION_INITIATED, HUMAN_REVIEW, AWAITING_OUTCOME, ESCALATED, REOPENED, RESOLVED. Rejection does not imply resolution.

## Evidence and reasoning

Evidence DTO is `dataset_v2.context.evidence_context` with extra private-field/reference sanitation. Nodes `{id,kind,properties}`; edges `{id,kind,start,end,properties}`. Own observation occurrence and recording must precede the snapshot; later outcome/case fixtures and gold labels are absent. Scalars/lists referencing withheld source entities are removed. Split/holdout/private model fields and import hash stamps are absent.

`triage` is explicitly `deterministic_evidence_rules`. Returns actual `assessment`, cited `diagnoses`, `recommendations` marked `PROPOSED` and requiring approval, `journey_forecast`, `operational_labels/status`, bounded `precedents`, `outcome:null`, limitations. Diagnoses include `summary_en/summary_ar` and recommendations `action_en/action_ar` using static reviewed templates; existing `summary/action` remain compatible. It does not call a model, execute an action or certify an outcome. Forecast uses connected remaining route travel bounds, the service promise, last corroborated custody and currently observed confident traffic; labels it `travel_window_estimate` with assumptions. A risk estimate yields a cited proposed SLA_RISK recommendation, while `assessment.supported_codes` remains strictly observed exception derivation. Unknown route position yields unavailable forecast. Hub/route/misdelivery labels derive visible comparison/proof results, not private recipes.

Historical GraphRAG matches shared supported exception codes through actual history Case->Resolution->Outcome, approving OperatorDecision->receipt-bearing ActionExecution->same Resolution, and bound `SUPPORTED_BY` observations. Requires verified non-invalidated bool success, coherent succeeded/failed status, provenance and chronology. Failed verified outcomes remain eligible. Maximum 20 candidate resolutions, 5 returned by default (maximum 10), 20 evidence entries per return. No pending outcomes or operational held-out data.

Map layers: `route_layers.layers.{expected_route,actual_route,vehicle_path,custody_points,hub_stops,delivery_attempts}` and per-layer `truncated` (200-point bound). Expected route contains `{segment_id,sequence,points}`; point DTO `{lat,lng,entity_id,source,occurred_at,evidence_id}`. Vehicle path adds `vehicle_id`, delivery attempts `disposition`. Actual route is compatible corroborated custody stops, not an interpolated parcel track. Vehicle telemetry is explicitly vehicle-only. Unsupported coordinates are omitted, not geocoded or fabricated.
