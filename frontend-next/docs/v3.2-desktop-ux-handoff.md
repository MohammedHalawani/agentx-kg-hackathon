## Implemented behavior

- Working agents moved into the existing left navigation. Expanded two-column tiles
  become vertical icon tiles when collapsed. Each actual assignment has a keyboard
  accessible tooltip and a case link. Selecting it only navigates. At most twelve
  assignments render per page; larger rosters remain accessible through paging.
- Assignment arrival/release uses 160 ms transitions. Selected animated icons use
  180 ms hover/focus transitions. Three small continuous indicators run only when an
  online snapshot reports both RUNNING and INVESTIGATING. Unknown, failed and
  disconnected states remain static. User and OS reduced-motion settings suppress
  animation. Pausing Auto prevents new assignments; an already RUNNING assignment
  can continue, matching the existing backend semantics.
- No idle worker identities are invented. Free capacity is explicitly a pool count.
  Worker identifiers and stages come from the API, with neutral unavailable labels.
  An explicitly empty V3 roster overrides a stale legacy single-case id.
- The old full-width investigation worker bar and Operations worker cards are removed.
  A guarded entry effect folds the nav once on entering Investigation; expanding it
  remains effective while moving between cases.
- A single testable classification function separates unassigned candidates, assigned
  investigations, Waiting and Closed. OPEN/REOPENED cases with a reported claim are
  excluded from new work. INVESTIGATING without a roster entry stays out of new work.
  Approvals, pending evidence/outcomes and rejected/escalated work remain Waiting.
- Search spans all loaded collections, including assigned and closed cases. The
  drawer also offers an explicit All loaded cases view. Audit/global search remain.
- The compact right sidebar keeps Waiting and Closed tabs. Closed includes reported
  closures, with separate verified/unconfirmed counts. A backend queue row alone
  never earns a verified check. The original rotating enrichment across the entire
  paginated resolved population and the stricter verification safeguards are retained.
- Search plus Filters replaces the crowded filter toolbar. The existing Radix Sheet
  provides draft/apply/clear, individual applied-filter removal, focus management and
  state retention when reopened. Filters cover supported collection, workflow,
  priority, city, cause, operational status and sort fields. Simulation clock, skip,
  Auto and refresh remain in a separate wrapping control row.
- Compact shadcn pagination navigates the actual loaded row array. Manual/cursor
  tables retain previous/next without clickable random-access page numbers. A
  truncated backend queue has an explicit loaded-subset notice. View audit is a
  secondary link outside pagination.
- Notifications use a single visible 300 px toast at the desktop top corner, below
  the header (mirrored for Arabic). Browser checks confirm it remains above the map,
  graph and inspector region at both requested resolutions.
- The one-case workspace, pipeline, evidence selection, route segmentation, graph
  focus and cross-case isolation remain. No backend, authority, contract, model,
  provider capacity, worker-limit, dataset or database change was made.

Only Users, Clock and MessageSquareText were adapted from Animate UI. They use the
existing Motion dependency; no new runtime dependency or entire icon library was
installed. Source URLs, adaptations and the complete upstream MIT + Commons Clause
license are preserved under `src/components/animate-ui/icons/`.

## Backend contract limits

The queue does not certify per-case claim eligibility. The backend additionally
checks development split, opened-at/clock, quiet-period timing, claims and pool
capacity. The browser does not receive every eligibility field. Consequently the
default view says **Open cases with no reported assignment**, rather than promising
that every row is eligible. The backend rechecks actual claims and authority.

The worker response contains assignments and aggregate capacity, not a roster of
named idle workers. It also does not establish whether an individual provider HTTP
request is currently running. Tiles describe reported investigation assignments;
provider calls remain subject to the unchanged gate. Unknown/disconnected snapshots
are explicitly unavailable/last-reported. These are reporting limits, not new API work.
