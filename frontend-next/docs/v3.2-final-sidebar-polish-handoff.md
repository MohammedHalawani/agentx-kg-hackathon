## Changes

The top-right Synthetic data box is removed from the header markup. Search,
connection status, language, theme and notifications retain their order with no
placeholder gap. Dataset metadata and evidence/audit provenance are preserved.
The existing demonstration/not-SPL disclosure remains in a sticky footer with
readable 10 px text, including while a long table scrolls. Its layout reserves
space for the existing Canopus launcher and supports Arabic.

The oversized queue came from a stretched grid cell, `height: 100%`, a 560 px
minimum card height and a 330 px/flexible list. Those constraints are removed.
The right column remains 268 px wide. The card, list, small pagination row,
statistics and secondary Resolution history link now follow intrinsic content
height. The summary is separated by a thin divider; nothing anchors it to the
table or viewport bottom.

Waiting and Closed each display at most four source records per page, with
independent page positions. Previous/next buttons disable at boundaries. Empty
queues show a compact message and 0 / 0 pages. Page indices clamp after removals;
the clamp is persisted so subsequent arrivals cannot revive an invalid old page.
Counts and verified/unconfirmed subcounts use the full loaded collection, not
the four visible records. Reported closure still requires authoritative detail
before it receives a verified check; it never becomes Waiting or new work.

Case links are keyed by actual case ID. Routine refreshes do not animate rows.
Unchanged links retain keyboard focus; if a polled removal unmounts the focused
row, focus moves to a remaining row or the empty panel. Tab controls support
arrow keys, Home and End. Native pagination buttons support keyboard activation,
translated accessible labels and mirrored RTL arrows. Existing reduced-motion
preferences continue to apply. No fabricated progress or optimistic resolution
state was introduced.

Working Agents, the filter drawer, main-table pagination, notifications, the
single-case workspace, pipeline, map/KG sizing and evidence synchronization were
preserved. No backend, dataset, inference, interface-contract or authority change
was made.

## Queue/count limitation

The existing service reads cursor pages, bounded to ten pages of up to 100 rows
per active/resolved scope. This limit and detail-enrichment limits are unchanged.
The mini-pagination navigates the loaded source records; it causes no additional
fetching or detail expansion.

If the service hits its read cap, the panel explicitly says **Loaded queue only**,
the pager adds **loaded**, and the statistics describe that loaded subset. The
API does not provide global Waiting, human-attention or verified-outcome
aggregates. The UI does not substitute a larger backend total for these counts or
promise unvisited/unreachable pages. For a cursor-only fixture advertising 5,000
rows per scope, the bounded read loaded ten records per scope and exposed exactly
three four-row display pages, with no request for cursor 10. Every advertised page
was reachable; next disabled at the actual loaded boundary.
